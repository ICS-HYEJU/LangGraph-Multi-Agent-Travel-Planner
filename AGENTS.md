# AGENTS.md

## Project Overview

This project implements a Korean multi-agent travel planner using LangGraph and LangChain.

The system generates personalized travel plans through four agents:

1. Agent 1: User Chat Manager
2. Agent 2: Plan Agent
3. Agent 3: Critic Agent
4. Agent 4: Local Expert / Recommender Agent

The system calls two remote OpenAI-compatible LLM servers:

- Light model server: used by Agent 1 and Agent 4
- Heavy model server: used by Agent 2 and Agent 3

## Core Architecture

Use a single LangGraph orchestrator.

Do not make Agent 1 responsible for controlling every internal transition.

Agent 1 is user-facing.

LangGraph Orchestrator controls graph routing, counters, termination, and errors.

Agent 2 sends its plan draft to Agent 3 for review.

This is not a command from Agent 2 to Agent 3.

It is a plan submission / review request step.

## Agent Roles

### Agent 1: User Chat Manager

- Analyze the user's natural language request.
- Create structured user requirements.
- Create the initial planning task.
- Detect missing initial required information.
- Ask clarification questions when needed.
- Format final responses for the user.

Required initial information:

- destination
- duration

### Agent 2: Plan Agent

- Generate a travel plan from structured user preferences.
- Use recommendations from Agent 4.
- Revise the plan based on Agent 3 feedback.
- Do not ask the user directly.

### Agent 3: Critic Agent

- Review the plan generated by Agent 2.
- Check user preference alignment, schedule density, movement feasibility, meal/rest balance, missing information, and excessive assumptions.
- Return exactly one of:
  - approved
  - need_revision
  - need_user_info
- Do not rewrite the full plan.
- Provide feedback only.

### Agent 4: Local Expert / Recommender Agent

- Provide local recommendations.
- Recommend places, restaurants, accommodation areas, movement tips, and cautions.
- Do not create the full travel plan.
- Provide materials that Agent 2 can use.

## Termination Rules

The system stops when:

1. Agent 3 returns approved.
2. Agent 3 returns need_user_info.
3. revision_count reaches MAX_REVISION_COUNT.
4. Agent 1 detects missing initial required information.
5. The orchestrator detects unrecoverable system failure.

## Counter Rules

- MAX_REVISION_COUNT defaults to 2.
- MAX_USER_QUESTION_COUNT defaults to 2.
- revision_count increases only during Agent 2 and Agent 3 revision loops.
- When the user provides additional information, reset revision_count to 0.
- user_question_count does not reset within the same travel planning session.
- Reset both counters only for a new travel request.
- If user_question_count reaches the limit, do not ask more questions. Make reasonable assumptions and continue.

## Implementation Rules

- Use Python 3.10 or higher.
- Use LangGraph for workflow control.
- Use LangChain's ChatOpenAI for OpenAI-compatible remote LLM endpoints.
- Use Pydantic for structured agent input/output.
- Keep prompts in `src/travel_agent_system/prompts/`.
- Keep agent node logic in `src/travel_agent_system/agents/`.
- Keep orchestration in `src/travel_agent_system/graph.py`.
- Keep shared services in `src/travel_agent_system/services/`.
- Keep utility functions in `src/travel_agent_system/utils/`.
- Do not hard-code IP addresses, model names, API keys, or port numbers.
- Read all endpoint settings from `.env` or environment variables.
- Use Korean for all user-facing responses.
- Use JSON-style structured outputs between agents when possible.
- Add tests for routing, schema validation, and counter behavior.
- Keep functions small and focused.
- Do not implement the entire system at once.
- Work phase by phase.
- Prefer small, reviewable changes.
- Do not create a web UI until the CLI prototype works.

## LLM Usage Rules

- Agent 1 and Agent 4 must use the light model.
- Agent 2 and Agent 3 must use the heavy model.
- Use `langchain_openai.ChatOpenAI`.
- Use OpenAI-compatible endpoints.
- Allow dummy API keys for local vLLM-style servers.
- All model names and base URLs must be loaded from `.env`.
